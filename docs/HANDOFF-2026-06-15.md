## Current Mainline

The app is now a SwiftPM macOS app named `DynamicIsland`.

The active product areas are:

- notch-aware black island shell
- default and music playback states
- compact artwork and low-overhead waveform bars
- phase-aware vertical hide/show and horizontal music skip gestures
- temporary in-memory File Shelf overlay
- display-profile adaptation for notched and non-notched screens
- per-launch JSONL interaction logs

Removed early-MVP areas must not be restored unless the user explicitly asks:

- `TaskActivityDataSource`
- `CodexUsageDataSource`
- `CCSwitchUsageDataSource`
- `StatusDotView`
- `AudioWaveformView`
- `DataPanelView`
- ECG or heartbeat waveform behavior
- `script/set_task_activity.sh`

## Current Verification

Use these commands after relevant changes:

```bash
swift run DynamicIslandCoreChecks
swift build --product DynamicIsland
./script/build_and_run.sh --verify
./script/build_and_run.sh
```

After launching, check the running process:

```bash
pid=$(pgrep -x DynamicIsland | head -n 1)
ps -o pid,stat,pcpu,pmem,etime,command -p "$pid"
```

For debug music-state testing:

```bash
./script/build_and_run.sh --debug-music-signal
ISLAND_DEBUG_MUSIC_SIGNAL_FILE=/tmp/dynamic-island-music-signal.json ./script/send_music_signal.sh playing
```

## Notes For Future Work

- Keep `DynamicIslandCore` free of AppKit and SwiftUI imports.
- Do not add persistence to File Shelf.
- Keep file logs sanitized; do not write raw paths or file names.
- Prefer `NotchMetrics`, `DisplayProfile`, and `IslandTopStatusBandLayout` over hard-coded display geometry.
- Keep hidden-shell behavior strict: only downward scroll may restore it.

# Island 超级详细交接文档

更新时间：2026-06-15

## 1. 项目一句话

这是一个面向 14 寸 MacBook Pro 的灵动岛式桌面应用，重点不是功能堆叠，而是把顶部 32pt 级别的空间做成一个可信、克制、连续的状态层。

## 2. 当前目标

当前产品重点已经明确到三个层面：

1. 顶部外壳和展开交互要稳定、连续、像一个实体。
2. 左侧状态点是任务活动的呼吸指示。
3. 右侧条纹默认/无音乐状态必须是一条安静的静态横线。

用户已经明确要求不保留心跳/ECG 代码；音乐播放时才允许右侧条纹进入动态波形。

## 3. 目前代码形态

项目是 SwiftPM 原生 macOS App，不是 Tauri，也不是网页壳。

- `IslandCore`：纯逻辑层，放尺寸、布局、波形模型、使用统计、状态模型。
- `Island`：AppKit + SwiftUI UI 层，控制顶部面板、展开收起、波纹、数据面板。
- `IslandCoreChecks`：当前最重要的验证入口，靠字符串检查和数值检查保护关键约束。

构建与启动入口统一使用 `script/build_and_run.sh`。

## 4. 关键运行方式

- 构建主程序：`swift build --product Island`
- 跑核心检查：`swift run IslandCoreChecks`
- 构建并启动：`./script/build_and_run.sh`
- 启动后可看进程：`ps -o pid,stat,pcpu,pmem,etime,command -p $(pgrep -x Island | head -n 1)`

当前已确认过，重启后 CPU 大约 0.5%，没有再回到之前的高占用卡死状态。

## 5. 核心文件地图

### `Sources/IslandCore/NotchMetrics.swift`

刘海和顶部外壳尺寸真相源。这里决定 closed/open 尺寸、刘海宽度、状态点安全区、展开后顶部区域的基准。

### `Sources/IslandCore/IslandTopStatusBandLayout.swift`

展开态顶部 32pt 带的区域合同。它把顶部空间切成：

- 左状态区
- 中间 camera housing 禁区
- 右信息区

状态点、右侧波纹、右上角成本徽章都依赖它。不要把这些东西随便挪回其他位置。

### `Sources/IslandCore/AudioPlaybackState.swift`

音频波形状态模型。

- `.idle`：静态基线
- `.audioLevels`：真实音乐播放波形

现在没有 `.heartbeat`，也没有 `fallbackHeartbeat`。默认无音乐 fallback 是 `defaultFallback == .idle`。

### `Sources/Island/Views/AudioWaveformView.swift`

实际绘制逻辑。这里有三个分支：

- `audioLevelsWaveform`：音乐播放
- `staticWaveform`：完全静态基线

不要再加入默认心跳分支。无音乐时只显示静态横线。

### `Sources/Island/Support/AudioPlaybackDataSource.swift`

音频状态来源。

默认逻辑仍是隐私友好的 AppleScript / app running state 路径，不默认启用 ScreenCaptureKit。

还有两个额外路径：

- `ISLAND_REAL_AUDIO_WAVEFORM=1`
- `ISLAND_CORE_AUDIO_TAP_WAVEFORM=1`

这两个都不应默认开启。

### `Sources/Island/Views/IslandOverlayView.swift`

顶部外壳和展开内容的 SwiftUI 视图。

这里有个重要点：

- `visibleAudioPlayback` 在折叠时被压成 `.idle`
- 展开后才真正显示右侧波纹

这可以避免折叠状态下持续动画抢 CPU。

### `Sources/Island/Controllers/IslandPanelController.swift`

AppKit 面板控制器。

它负责：

- 初始化顶部透明面板
- 开关展开状态
- 任务状态轮询
- 音频状态轮询

音频轮询频率是约 83,333,333ns，也就是大约 12fps 级别的状态抓取，绘制层再用 `TimelineView` 做连续动画。

### `Sources/Island/Views/DataPanelView.swift`

数据面板。

现在是比较固定的 header contract：

- `Status / Stats / Tools`
- `Stats` 下面还有 `Trends / Overview / All`
- `30s` 刷新 badge
- `Today / 7d / 30d / All` 时间范围
- 右上角 top cost badge

这些位置和层级已经被多次调过，不要轻易移动，否则容易把顶部空间打乱。

### `Sources/Island/Support/CodexUsageDataSource.swift`

Codex 使用量来源。默认读 `~/.codex/sessions/**/*.jsonl`，优先使用 `token_count.info.total_token_usage` 的快照 delta，必要时回退 `last_token_usage`。

### `Sources/Island/Support/CCSwitchUsageDataSource.swift`

CC Switch 数据源，当前用于更准确的成本/usage 口径。

这里有个已经解决过的细节：cache hit 相关展示应当基于包含 cache read 的输入口径，不要只看 fresh input。

### `Sources/Island/Support/TaskActivityDataSource.swift`

任务活动状态来源。

默认从 Codex session 事件和最近写入时间推断；`~/Library/Application Support/Island/task-activity-state.txt` 只是短时人工覆盖，不是永久真相。

## 6. 最近最关键的决策

### 6.1 默认条纹的最终方向

最新用户要求很明确：

- 默认状态是最初的一条静态线
- 不保留 ECG/心跳代码
- 不播放音乐时不要动
- 播放音乐时才显示音乐波形

因此当前正确形态是：

- 细线
- 克制
- 静态
- 不抢右侧金额 badge 的注意力

### 6.2 音乐与默认线的关系

音乐播放和默认静态线是两条不同状态：

- 播放音乐时，用音乐波形
- 没有音乐时，用静态横线

不要把无音乐状态做成任何自动动画。

### 6.3 顶部空间纪律

顶部 32pt 区域非常贵，不能随便塞内容。

已经固定的东西：

- 左状态点
- 右侧波纹
- 右上角成本 badge
- 中间 camera housing 禁区

## 8. 历史坑位

### 8.1 之前的心跳动效导致 CPU 飙高

曾经的错误是把绝对时间直接拿去做历史 beat 累加，导致每帧都在循环极大量数据。这个问题已经修过，不能回退到那种写法。

### 8.2 隐藏态还在动画

曾经折叠时 waveform 仍然在动画，导致 hover 卡顿。现在折叠态已经压成 `.idle` 或静态表现，避免隐藏动画耗 CPU。

### 8.3 不要默认启用系统录屏/共享指示

用户不喜欢菜单栏被共享/录制指示占空间，所以默认不要开 ScreenCaptureKit。

## 9. 现在的实现约束

1. 不要恢复默认心跳/ECG 动画。
2. 不要让无音乐状态自动动起来。
3. 不要在折叠态持续跑高频 Timeline 动画。
4. 不要默认启用屏幕采集。
5. 不要破坏顶部 32pt 区域的布局合同。
6. 不要把数据面板和顶部外壳搅成一团。

## 10. 当前验证命令

建议后续每次动这些文件时都跑：

```bash
swift run IslandCoreChecks
swift build --product Island
./script/build_and_run.sh
```

如果怀疑顶部布局或 CPU 问题，再补：

```bash
pid=$(pgrep -x Island | head -n 1)
ps -o pid,stat,pcpu,pmem,etime,command -p "$pid"
```

## 11. 后续建议顺序

1. 先保住默认静态横线和低 CPU。
2. 再确认音乐播放下的波纹是否足够真实、连续。
3. 再收敛顶部信息排版和数据面板密度。
4. 最后才考虑更复杂的状态源或功能扩展。

## 12. 回退策略

如果后续某次改动把默认静态线弄坏了，优先检查：

1. `Sources/Island/Views/AudioWaveformView.swift`
2. `Sources/IslandCore/AudioPlaybackState.swift`
3. `Sources/Island/Support/AudioPlaybackDataSource.swift`
4. `Tests/IslandCoreChecks/main.swift`

如果恢复后又出现 CPU 升高，优先检查默认/折叠状态是否又在跑持续动画。
